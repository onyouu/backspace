# 지도 실패와 교사 모델을 분리한 결과

2026-10-08, Asia/Seoul. 실제 자료 검증 기록: `output/graph_optional/repair_report.json`.

자료 9개와 기존 이해 노트 121개를 그대로 사용했습니다. 지도 1/9 상태에서 잠정 교사 모델을 먼저 생성했고, 이후 실패 파일 8개를 재검증해 4개를 파일 전체 기준으로 복구했습니다. 현재 지도는 5/9입니다. 학생의 실제 수행과 검증된 교사 가설은 아직 관찰되지 않았습니다.

1. **기존에 막히던 이유**

   웹 흐름은 지도 저장 → 지도 뷰 → 반복 패턴 성공 후에만 교사 모델 생성으로 넘어갔습니다. 저장된 이해 노트가 있어도 패턴 단계가 실패하면 `usable_patterns_required`로 대기했습니다. 새 가설 생성도 두 문항의 반복 그래프를 요구했습니다.

2. **제거한 연결**

   이해 노트 저장소가 있는 작업공간에서는 패턴 성공 여부와 무관하게 교사 모델을 만듭니다. 웹은 느린 지도 재시도에 들어가기 전에 현재 노트로 모델을 먼저 저장합니다. 지도 없는 작업공간도 지원하며, 기존의 그래프 기반 CLI와 명시적 재구성 기능은 유지했습니다.

3. **지금 교사 모델이 읽는 자료**

   현재 버전과 일치하는 노트 원문·출처 → A-MEM 관련 노트 검색 → Jev의 교사 관련성·새 해석 필요성 판정 → 제한된 새 가설 제안 → Jev의 통합·지지·반박 판정 → Python 상태 갱신 순서입니다. 기존 문항 근거와 가설도 재사용합니다. 개념 지도와 반복 패턴은 있을 때 보강하며, 노트를 대신하지 않습니다. 새 가설 요청에는 전체 PDF를 보내지 않습니다.

4. **SourceSpan에 저장하는 것**

   구절 ID, 자료 ID와 SHA-256, 원문 버전, 페이지/위치, 영역 ID, 시작·끝 문자 위치, 실제 텍스트, 자료 종류, OCR 근거, 인식 버전, 현재/이전 상태를 저장합니다. `source_span.schema.json`이 계약입니다. 원문과 인식 버전이 바뀌면 ID도 달라지고 이전 목록은 `source_spans/history/`에 보존됩니다. 새 원문에 이전 ID를 억지로 붙이지 않습니다.

5. **인용 방식이 바뀐 코드**

   `source_spans.py`가 원문 구절을 만들고 검증합니다. `span_graph.py`에서 모델은 구절 ID만 선택합니다. `span_question.py`는 문항 경계·과제 근거·주장·평가기준의 모델 출력도 ID로 받습니다. 실제 인용 문장은 Python이 복원하고, 기존 JSON을 읽는 기능과 원문 검토 화면을 위해 저장합니다. `model.py`는 현재 원문 버전과 좌표를 검증합니다. 예전 저장 파일의 인용 형식도 계속 읽을 수 있습니다.

6. **지도 분석을 나눈 방식**

   A는 개념과 근거 ID, B는 개념 ID 사이 관계와 근거 ID, C는 필요한 경우의 사고 절차, D는 Jev의 강조 분류입니다. 각 요청과 결과가 따로 저장됩니다. 개념이 하나인 구간은 B를 생략하고, C는 Jev가 필요하다고 판정해야 실행합니다. B가 실패해도 A는 보존됩니다. 원본 그림 입력과 독립된 그림 관계 검토도 유지했습니다. 작은 계약은 각각 `concept_extraction`, `relation_extraction`, `reasoning_extraction` 스키마로 남겼습니다.

7. **강조 때문에 전체 결과를 버리지 않도록 변경**

   강조를 explicit / repeated / structural / inferred / none으로 구분합니다. explicit은 현재 구절 ID와 실제 강조 표기가 필요합니다. repeated는 서로 다른 구절의 반복 근거가 필요하고, structural은 직접적인 “중요하다” 문구를 요구하지 않습니다. inferred는 Jev가 분류한 추정으로 저장합니다. 잘못된 강조 항목만 제외하며, 개념 전체는 남깁니다. 비명시적 강조를 기존 explicit 횟수에 더하지 않습니다.

8. **교사 모델의 준비 상태**

   not_ready는 유효한 근거 없음, provisional은 근거를 모았으나 해석 검증 부족, usable은 적용 조건·복수 자료·Jev 지지가 확보된 잠정 활용 상태, well_supported는 독립된 문항 증거까지 확보된 상태, needs_review는 강한 반례나 적용 범위 검토가 필요한 상태입니다. 완료 단계 수로 상태를 올리지 않습니다. 현재 실제 자료의 모델은 **provisional**입니다.

9. **가설별 상태와 지도 지원 상태**

   기존 candidate / active / weak / contested / retired / rejected를 유지하면서 별도의 readiness와 graph_support=pending/available을 저장합니다. 지지·반박·약화 근거 ID, 자료 다양성, 실제 독립 문항 수, 적용 조건, Jev 결정 ID와 변경 이력을 보관합니다. `teacher_hypothesis_state.schema.json`이 새 상태 계약입니다. 노트 여러 개를 독립 시험 문항으로 세지 않습니다.

10. **현재 실제 자료 결과**

    이해 노트 121/121, 근거가 등록된 자료 9/9, 완료 지도 5/9입니다. 이 숫자는 자료 등록·분석 범위이며 교사 성향이 검증되었다는 뜻은 아닙니다. 실제 시험 문항 그래프는 0개이고, 현재 확인된 교사 가설도 0개입니다. 기존 Jev의 노트 분류·원문 판단과 새 가설에 대한 관계 판단을 구분합니다. 가설이 없으므로 가설 관계 판정의 할당 대상은 0/0입니다. API 미연결을 뜻하지 않습니다.

11. **지도 1/9에서도 모델이 만들어졌는지**

    확인했습니다. `primary_live.json`에는 지도 1/9, 노트 121/121, 자료 9/9에서 생성된 잠정 모델 기록이 있습니다. 이후 지도 근거만 추가해 모델 표시 버전을 갱신했습니다. 모델 전체를 NVIDIA로 다시 작성하지 않았습니다. 원문/OCR/노트 파일 해시 비교에서도 변경이 없었습니다.

12. **실패 8개 파일 재검증**

    아래 성공은 몇 문항·몇 페이지의 샘플이 아니라 해당 파일의 모든 분석 구간을 처리하고 저장 검증까지 통과한 결과입니다. API 응답을 받았다는 이유만으로 관계를 채택하지 않았으며, Jev가 지지하지 않은 관계는 제외했습니다.

    | 자료 | 결과 |
    |---|---|
    | (4) 생태계의 구조와 기능 | 파일 전체 복구 |
    | (7) 신경자극의 전도와 시냅스 전달 | 파일 전체 복구 |
    | 생명시스템의 구성단계 | 파일 전체 복구 |
    | (6) 신경자극의 전도와 시냅스 전달 | 파일 전체 복구 |
    | 생물과 생명과학의 특성 | 개념 단계 schema_invalid, 후속 구간 대기 |
    | (5) 개체군과 군집의 특성 | 개념 단계 invalid_json, 후속 구간 대기 |
    | (3) 기관계의 통합적 작용 | 개념 단계 invalid_json, 후속 구간 대기 |

    새 분석에서 quote 문자열 오류로 파일 전체가 중단된 경우는 없었습니다. 강조 오류와 근거가 부족한 관계는 항목별로 격리됐습니다. 개념 배열 한도를 넘긴 응답에는 저장 허용 상한을 조정했지만 해당 파일의 전체 재검증은 남아 있습니다. 여러 구절을 근거로 붙인 결과를 기존 저장 규칙이 거부하던 문제도 수정했습니다. 이 수정으로 복구한 2개는 성공한 체크포인트만 읽었고 추가 NVIDIA 호출을 차단한 상태에서 검증했습니다.

13. **남아 있는 원문 인식·해석 문제**

    일부 원문에는 선택지 숫자나 깨진 표기만 남아 있고, 기존 노트가 그보다 자세한 설명을 붙인 사례가 있습니다. 기존 구조도 지도에도 `Bold`, 숫자처럼 개념으로 보기 어려운 표기가 남아 있습니다. 구절 ID는 이런 글자를 정확히 추적할 뿐, 글자를 올바르게 읽었다거나 의미 해석이 맞다고 보장하지 않습니다. 작은 그림 글자·배치·화살표·공유 지문은 원본 검토와 별도의 정확도 검증이 필요합니다. 이번에는 OCR을 다시 생성하지 않았고 handwriting 모델을 새로 도입하지 않았습니다. 기존 OCR 후보는 삭제하지 않으며, 이후 자료 변환에서도 후보/선택 정보가 있으면 구절의 provenance로 전달합니다.

14. **검증 결과와 실행 주소**

    Python 회귀 검증 218개와 JavaScript 정적·기능 검증이 통과했습니다. 새 검증에는 요청한 A–H, 원문 변경 시 이전 ID 거부, 원본 그림 전달, 다중 구절 저장, 문항 ID 출력 및 인용 복원, 잘못된 보조 지도 입력의 격리가 포함됩니다. 모의 자료의 조건을 충족하면 지도 없이 usable 가설이 생기는 것도 확인했지만, 이를 실제 9개 자료의 정확도 결과로 해석하지 않습니다. 데스크톱 1440px·모바일 360px에서 상태와 범위 표시를 확인했고 모바일 가로 넘침은 없었습니다. 원본 보존·두 자료 공간·100MB 업로드 제한은 유지했습니다.

    새 실행 주소: http://127.0.0.1:8784/#model . 기존 서버 주소는 이번 변경을 모두 로드하지 않았으므로 새 주소를 사용합니다.

개발자가 다시 검증할 때는 `python -m scripts.validate_graph_optional`을 사용합니다. `--source-id`로 파일을 좁힐 수 있고, `--cached-only`는 저장된 결과가 없을 때 NVIDIA 호출을 차단합니다. 결과는 파일별로 보관하며, 부분 성공을 파일 전체 성공으로 표시하지 않습니다.
