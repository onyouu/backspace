# 교사 모델을 조금씩 갱신하도록 바꿨습니다

이제 새 자료가 들어올 때마다 교사 가설을 처음부터 다시 쓰는 대신, 기존 가설에 새 근거를 붙입니다. **같은 경향이 반복되면 지지를 추가하고, 직접 충돌하면 반례를 남깁니다. 새로운 사고 패턴이 필요할 때만 NVIDIA가 새 가설 하나를 제안합니다.**

원래 코드를 확인해 보니 Teacher Model을 저장하는 부분은 이미 Python이었습니다. 느린 부분은 그 앞에서 NVIDIA가 교사 가설 묶음을 생성하는 단계였습니다. 그 단계의 기본 흐름을 바꿨습니다.

## 무엇이 달라졌나

예를 들어 기존 가설이 “조건을 비교하고 판단 근거를 제시하도록 요구한다”라면:

- 같은 요구를 가진 새 문항 → 지지 근거를 추가합니다. NVIDIA로 가설을 다시 쓰지 않습니다.
- 같은 조건에서 다른 기준을 명확히 요구하는 문항 → 반례를 추가합니다. 기존 가설과 이력은 남깁니다.
- 특정 단원에서만 맞는 근거 → 적용 범위를 좁히는 후보를 남깁니다. 바로 전체 수업의 특성으로 확정하지 않습니다.
- 관련 없는 문학 지문 → 가설을 바꾸지 않습니다. 무관한 내용은 반례가 아닙니다.
- 판단이 모호하거나 API가 실패한 경우 → 근거를 보존하고 확인 대기로 둡니다.

가설에는 ‘후보’, ‘근거가 쌓인 잠정 가설’, ‘지지 부족’, ‘반례 확인 중’, ‘보관’, ‘검토 제외’ 상태가 생겼습니다. 처음 제안된 문장을 바로 공부계획의 확정 기준으로 쓰지 않습니다. 새 증분 모델에서는 충분한 근거가 있는 가설만 계획에 전달하고, 범위 수정이 확인 대기인 가설도 제외합니다. 기존 모델은 계속 읽을 수 있습니다.

## 새 가설이 만들어지는 과정

관련 자료와 문항을 작은 묶음으로 고른 뒤 Jev가 먼저 기존 가설로 설명되는지 판단합니다. 이미 설명된다면 새 문장을 만들지 않습니다. 설명되지 않는 반복 패턴이면 NVIDIA가 조건부 가설 하나를 제안합니다. 다시 Jev가 기존 가설과 중복되는지, 더 좁은 변형인지, 새로운 가설인지 검토합니다.

중복 가설은 새로 활성화하지 않습니다. 독립된 가설도 서로 다른 문항 2개 이상, 독립 원자료 2개 이상, 충분한 검토 범위와 지지, 강한 미해결 반례가 없다는 조건을 통과해야 잠정적으로 활성화합니다. 이 조건을 못 채우면 후보로 남습니다.

## 실패해도 완료된 부분은 남습니다

새 가설을 만드는 순간 NVIDIA가 실패하면 “새 가설 생성 대기”로 저장합니다. 기존 가설의 지지·반례 갱신까지 함께 실패 처리하지 않습니다. Jev의 낮은 확신도 ‘무관’이나 ‘중요하지 않음’으로 바꾸지 않습니다.

노트의 부가 정보나 연결을 만드는 A-MEM 단계가 실패해도, 이미 저장한 본문과 출처를 사용해 이어갑니다. 검색 장애가 있으면 출처가 맞고 거절되지 않은 저장 본문만 제한적으로 사용합니다. 원문·OCR·노트·그래프·이전 모델 이력은 보존합니다. NVIDIA 시간 제한은 늘리지 않았습니다.

## 확인한 결과와 남은 한계

새 증분 갱신 테스트 23개와 A-MEM 장애 테스트 1개를 포함한 전체 152개가 통과했습니다. 웹 화면의 코드·지도·모션 관련 검사도 통과했습니다. 지지, 무관, 반박, 범위 축소, 새 가설 생성, 중복, 두 API의 실패, 재실행, 출처 변경, 피드백과 계획 연결을 확인했습니다.

실제 `(3) 02. 기관계의 통합적 작용~.pdf`의 4·5·6페이지와 무관한 2페이지 지문으로 작은 API 비교도 했습니다. **현재 작업공간에는 완성된 실제 교사 가설 3–5개가 없었습니다. 따라서 원문을 바탕으로 만든 잠정 문장 3개를 비교용으로 저장했습니다. 검증된 교사 모델로 배포하지 않았습니다.**

| 같은 작은 원자료의 판단 비교 | NVIDIA 재해석 대조 | Jev 증분 판단 |
|---|---:|---:|
| NVIDIA 실제 요청 | 2회 | 0회 |
| Jev 요청 | 0회 | 6회 |
| 걸린 시간 | 21.433초 | 3.820초 |
| 네트워크 실패 | 0 | 0 |
| 잘못된 JSON | 1건 후 대체 모델로 완료 | 0 |
| 관련 근거 | 문장 3개 재해석 | 적용 범위 불확실 → 3건 확인 대기 |
| 무관한 지문 | 관계 분류 정확도 미측정 | 3건 모두 무관, 반례로 저장하지 않음 |
| 확정된 가설 변경 | 해당 없음 | 0건 |
| 같은 근거 재실행 | 해당 없음 | 추가 요청 0회·중복 갱신 0건 |

이 비교는 **새 갱신 경로의 작은 실제 자료 점검**입니다. 기존 전체 시험 분석을 끝낸 모델과의 성능 비교도, 교사 해석의 정확도 인증도 아닙니다. 빠르다는 이유로 관련 근거를 억지로 확정하지 않았습니다. 완성된 실제 교사 가설이 쌓이면 요청한 3–5개 기존 가설 비교를 같은 방식으로 추가할 수 있습니다.

## 사용 방법

웹의 교사 모델 작업은 기본적으로 새 갱신 경로를 사용합니다. 이미 올린 자료를 자동으로 다시 분석하지 않았습니다. 새 코드의 서버를 열고 교사 모델 갱신을 실행하면 됩니다.

CLI에서는 그래프와 반복 패턴을 저장한 뒤:

```powershell
.\.venv-ocr\Scripts\python -m backspace_mvp update_teacher_model --state state\web\workspace\teacher\dataset.json
```

기존 전체 가설 생성이 필요할 때만 `--manual-rebuild`를 명시합니다. 기존 `build_teacher_hypotheses`, `score_teacher`, `build_teacher_model` 명령도 유지했습니다. 스키마/질문 버전 변경이나 손상된 증분 상태는 자동 초기화하지 않고 명시적 복구·마이그레이션을 요구합니다.

사람의 확인·거절·범위 수정과 실제 시험 피드백은 `teacher_feedback` 명령으로 별도 저장할 수 있습니다. Jev의 이전 판단을 덮어쓰지 않으며, 이후 갱신에서 반영합니다. 전체 자동 계획 재작성, 학습/보정 시스템, 여러 가설을 동시에 탐색하는 기능은 이번 범위에 추가하지 않았습니다.
