# Teacher Model 개선 결과 — 쉽게 보는 변경 보고서

## 1. 이전 동작

교사 특징을 증거별로 갱신하는 기능은 이미 있었다. 새 가설을 만들 때는 Jev가 먼저 살펴봤지만, 기존 가설에 새 학습자료를 연결하는 두 경로에서는 사전 선별을 건너뛰었다. 일반 교과 설명에도 가설별 관계 판단 요청이 나갈 수 있었다. Teacher Model 전체를 NVIDIA가 새로 쓰는 구조는 현재 기본 경로에 없었다.

## 2. 지금 동작

원자료 → 이해 노트/그래프 → 관련 가설 찾기 → **증거 하나를 Jev가 먼저 선별** → 필요한 가설별 관계 판단 → Python 상태 갱신.

새로운 반복 사고 구조는 기존대로 Jev 선별 → 새 의미 필요 여부 → NVIDIA 후보 하나 → Jev 통합 확인 순서다. OCR·그림 이해·누적 그래프·문항 그래프·계획·실패 후 재개 기능은 유지했다.

## 3. 무엇을 수정했나

`teacher_update.py`에 공통 `update_related_evidence`를 추가했다. `teacher_incremental.py`의 그래프 기반 갱신과 `teacher_note_evidence.py`의 이해 노트 기반 갱신이 모두 이용한다. 같은 증거에 관련 가설이 여럿이면 선별은 한 번만 한다. 각 경로에서 해당 원문과 가설에 맞춰 기존 메모리를 조회한다. 코드 변경 감지에는 이 모듈들도 포함했다.

정확한 위치와 기존 함수 12개 조사 항목은 [코드 조사 기록](teacher_update_audit_20261007.md)에 있다.

## 4. Jev에게 묻는 질문

선별은 교사의 설명/평가 방식이 나타나는지, 일반 교과 지식인지, 기존 가설과의 관련성, 새 정보량을 각각 묻는다. 서로 독립된 질문이다. 일반 지식 여부가 모호해도 교사 특징이 확실하면 다음 판단으로 갈 수 있다.

관계 판단은 한 요청에서 5개 질문을 묻는다: **어떻게 연결되는가 / 근거 강도 / 적용 범위 / 새로운 패턴인가 / 새 해석이 필요한가**. 강화·약화·반박·범위 축소/확장·무관·판단 유보를 구분한다. 무관은 반례가 아니다.

## 5. 질문 버전

기존 문구와 버전 `teacher-relation-v1`, `teacher-prefilter-v1`, `teacher-novelty-v1`, `candidate-integration-v1`, `teacher-sufficient-v1`을 유지했다. 기존 결정은 질문 내용·버전·모델·임계값과 함께 보존한다. 문구나 정책을 바꾸면 이전 판단을 자동으로 다시 해석하지 않고 명시적 마이그레이션이 필요하다.

## 6. 저장 구조

독립 가설, 원문 증거, 증거-가설 관계, 변경 이력, 후보, 판단 대기, 사람/시험 피드백을 기존 원자적 체크포인트에 유지한다. 선별 결과용 `prefilters`를 추가했다. 이는 기존 상태에 추가 가능한 필드로, 기존 관계/가설/질문 버전은 변경하지 않는다.

선별 기록은 `schemas/teacher_prefilter.schema.json`으로 검증하고 `teacher_model/prefilters/`에도 저장한다. 원문 위치·해시·대상 가설·판단 ID를 남긴다. 실제 확률·점수·confidence와 원문 문맥은 연결된 Jev 결정 기록에서 확인한다. 일반 교과 지식은 **generic_evidence_preserved**로 기록하고 노트/원본을 삭제하지 않는다.

## 7. 가설 변화는 어떻게 기록되나

기존 델타가 변경 전/후 상태, 모델 버전, 증거 ID, 가설 ID, Jev 결정 ID, 시간을 기록한다. 일반 설명으로 제외한 증거는 가설을 바꾸지 않는다. 무관 판정도 가설 지지/반례를 바꾸지 않는다. 반박 증거는 contested 상태를 만들 수 있으나 가설을 삭제하지 않는다. 승격 시 오래된 원문 버전의 관계를 다시 세지 않도록 해시 검사를 보완했다.

## 8. NVIDIA를 호출하는 경우

관계 판정·지지 수 계산·상태 변경에는 NVIDIA가 필요 없다. 반복 구조가 기존 가설로 설명되지 않거나 새 해석이 필요하다고 Jev가 판단할 때만 작은 근거 묶음으로 후보 하나를 요청한다. 이번에 timeout은 늘리지 않았다. 자료를 읽고 의미를 이해하는 NVIDIA 호출은 별도 역할로 유지한다.

## 9. 호출이 얼마나 줄었나

일반 설명 하나에 관련 가설 4개가 있으면, 이 갱신 단계에서 기존 관계 요청 4번 대신 선별 요청 1번으로 끝날 수 있다. 이미 저장된 일반 설명 선별은 재실행에서 호출도, 변경 증거 예산도 다시 차지하지 않는다. 반대로 유효한 증거는 선별 1번이 추가되므로 모든 입력에서 호출 수가 줄어든다고 말할 수 없다.

아래 실제 소규모 실험에서는 불확실성 때문에 관계 판단을 보류했다. 이것을 정확도 개선이나 모든 작업의 시간 단축으로 해석하면 안 된다. NVIDIA 단계는 이번 소규모 실험의 이전/이후 모두 0회이므로 이번 보완 자체의 NVIDIA 절감률을 주장하지 않는다.

## 10. 실패하거나 애매하면

Jev 연결 실패/모호한 선별은 pending_review다. 실패를 무관/낮은 중요도로 바꾸지 않는다. 연결 실패는 재시도하고, 성공했지만 모호한 동일 판단은 캐시를 유지해 반복 과금을 막는다. 원문/가설 조건 변경 또는 검토가 필요하다.

실제 시험문항과 이미 확인된 반례는 일반 교과 설명 판정만으로 제외하지 않는다. 메모리 검색 장애는 해시가 맞는 원문 연결 노트로 대체한다. NVIDIA 후보 생성이나 후보 통합 실패는 앞서 완료한 관계/노트를 지우지 않는다. 수동 재생성도 기존 함수를 유지한다.

## 11. 자동 검증

기존 A–I, 원문 보존, 중복 방지, 후보 생성 실패/통합 재개 테스트를 유지했다. 새 테스트는 일반 설명 보존/호출 생략/재실행, 선별 요청 공유, 실패 재시도, 모호한 선별 유보, 독립 질문의 모호함 처리, 실제 문항/반례 보호, 원문·가설 변경, 이전 체크포인트 호환, 오래된 관계 제외를 확인한다. **전체 Python 테스트 203개 통과**, 웹 JavaScript/그래프/진행창/모션 검사도 통과했다. 테스트 중 코드 수정으로 변경 감지 장치가 작동했던 실행은 실패로 남겼으며, 코드 고정 후 새 프로세스에서 전부 통과한 결과를 최종 결과로 사용한다.

## 12. 실제 자료 실험과 한계

현재 실제 작업공간은 완료된 교사 가설 0개, 문항 그래프 0개다. 요청한 **기존 실제 가설 3~5개 비교는 아직 수행할 수 없다**. 실제 기관계 PDF 4쪽과 명시적으로 만든 잠정 비교 문장 3개를 별도 폴더에서 사용했다. 프로그램의 교사 모델이나 원자료는 바꾸지 않았다.

첫 Jev 실행: **4회 / 2.004초 / 연결 실패 0 / NVIDIA 0회**. 선별 4건 모두 판단 대기였다. 관계 후속 요청 0회, 바뀐 가설 0개, 중복 변경 0개, 원문 인용 보존 확인. 같은 입력 재실행은 추가 API 호출 0회였다.

잘못 반박/무관으로 확정한 사례는 0개였지만, 아무 관계도 확정하지 않았으므로 정확도가 높다는 뜻은 아니다. 자료에 교사 특징이 나타나는지 Jev가 확신하지 못했다. 전체 문항 분석이나 교사 특징의 실제 품질 검증은 완료되지 않았다. 로그는 로컬 `output/teacher_incremental_validation/prefilter-20261007/`에만 보존한다.

이전 기록의 NVIDIA 2회·21.433초 대 Jev 6회·3.820초는 **과거에 수행한 작은 재해석 비교**이며 전체 파이프라인/현재 보완의 실측 결과가 아니다. 최신 실험과 섞어 절감률을 계산하지 않는다.

## 13. 전체 재생성이 필요한 경우와 다음 검증

전체 재생성은 명시적 수동 실행·스키마/질문 버전 변경·손상 복구·지정 benchmark에 제한한다. 원문/정책 불일치는 조용히 초기화하지 않는다. 이번 변경은 가설 문구나 임계값을 낮춰 통과시키지 않았다.

다음 품질 검증에는 실제 문항 그래프와 완료된 조건부 교사 가설, 사람이 확인한 지지/반례가 필요하다. 그것이 확보되면 관련 증거를 일반 설명으로 잘못 제외하는지, 반례를 놓치는지, 후보 생성이 정말 필요한 때에만 실행되는지를 비교한다. 현재 남아 있는 원자료 그래프 단계의 대기 작업은 별도 과제로 남아 있다.
