# 오류 수정 및 검증 기록 — 2026-10-06

## 신고된 실패

`output/nvidia_runs/a741188a065c408ca05e3d6c062ea989.json`에서 학습자료 p4 분석의 Lightning 시간 초과와 Super `finish_reason=length`를 확인했다. 대체 모델도 같은 3,072토큰 제한을 사용해 JSON이 끝나기 전에 잘렸다.

실제 p4 재현에서는 6,144토큰으로 늘린 요청이 완전한 JSON을 반환했다. 이어서 관계 끝점 `소화`가 개념 목록에 빠진 검증 오류도 발견했다. 이 이름은 원문에 독립된 표기로 존재하므로 정확한 원문 관찰로만 보완하고 관계 의미는 별도 모델 검토를 거쳤다. 원문에 없거나 다른 단어의 일부인 이름은 보완하지 않는다.

NVIDIA의 출력 한도와 추론 설정은 [공식 API 문서](https://docs.api.nvidia.com/nim/reference/nvidia-nemotron-3-super-120b-a12b-infer)를 참고했다.

## 수정

- 출력 잘림은 같은 모델에서 한도를 두 배로 늘려 재요청한다. 환경의 `NVIDIA_MAX_TOKENS`를 초과하지 않으며 `complete()`당 최대 3회다. 의미 검증의 별도 보정 단계는 기존처럼 최대 1회다.
- 확장된 응답에 맞춰 대기시간을 늘린다. 기본 45초에서 90초, 필요 시 180초까지다. 더 긴 시간을 명시한 사용자 설정은 유지한다.
- 같은 작업에서는 성공한 모델과 해당 JSON 계약의 출력 한도를 재사용한다. 매 페이지마다 실패 모델을 다시 기다리는 문제를 줄였다. 웹 작업은 자료 종류별 제공자 인스턴스를 공유한다.
- 잘못된 응답 외피·JSON·연결 중단을 구분한다. 로그에는 JSON 오류 위치만 기록하고 키·원문·내부 추론은 넣지 않는다.
- 기존 실패 후보도 동일한 요청 해시 아래에서 스키마와 원문 검증을 다시 통과하면 복구한다. 잘린 JSON은 채택하지 않는다.
- 분석 단계와 캐시 재사용 여부를 실제 작업 상태로 표시한다. 읽기 실패는 파일 목록에 남기며 성공한 재시도에서 해제한다.
- 새 교사 자료는 모델을, 새 시험범위·수정한 인식 결과는 계획을 오래된 상태로 표시한다. 시험 식별자도 함께 비교한다.
- 시험범위 분석 뒤 지도가 즉시 갱신되도록 했다. 일정은 90일차까지 탐색할 수 있다.
- 중복 작업 시작·중복 완료 클릭을 막고, 여러 파일 중 일부 업로드가 실패해도 성공한 파일을 갱신한다.
- 일시적인 상태 조회 실패 시 서버 작업을 계속 추적한다. 이전 완료 알림의 타이머가 새 작업 알림을 숨기지 않는다. 실패 알림은 직접 닫을 때까지 남긴다.
- 작업 실패 이후에도 모델·시험범위·계획이 없는 상태의 생성·메모 버튼은 비활성으로 유지한다. 늦게 도착한 이전 작업의 응답이 새 작업 상태를 덮어쓰지 않는다. 최신 실제 작업공간의 빈 계획 화면에서도 확인했다.
- 원문 저장 중 추가 입력·포커스·한글 입력창을 보존한다. 저장 후 편집창 전체를 다시 만들지 않고 상태·이력만 갱신한다. 저장 실패·미저장 닫기 확인도 유지한다.
- 메모 저장 중 이동하거나 추가 입력해도 새 입력을 지우지 않는다. 로컬 폰트도 Python 패키지 포함 목록에 넣었다.
