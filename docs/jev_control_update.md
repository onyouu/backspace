# 필요한 분석만 실행하도록 바꿨습니다

지금까지는 자료를 이해한 뒤에도, 노트의 검색 정보를 만들고 기존 노트와 연결하는 일을 NVIDIA에 계속 맡겼습니다. 이미 아는 내용이 반복돼도 새 해석을 만드는 모델을 다시 불렀습니다. 답변이 길어지면 같은 요청의 출력량과 대기 시간을 늘려 반복하는 방식도 있었습니다.

이번에는 **Jev가 먼저 확인하고, 새 해석이 필요한 경우에만 NVIDIA를 추가로 부르도록** 바꿨습니다. PDF 읽기, 그림 분석, 노트, 기존 그래프, 교사 모델, 계획 기능은 유지했습니다.

## 자료를 넣었을 때 달라지는 점

자료를 읽어 이해 노트를 만드는 첫 작업은 여전히 NVIDIA가 합니다. 그다음 기존 노트를 찾아, 같은 설명인지·새 설명인지·충돌하는 내용인지를 Jev가 확인합니다. 분류, 중복, 충돌, 추가 분석 필요성, 그래프 필요성을 **한 번에 묻습니다.** 질문마다 따로 API를 부르지 않습니다.

이미 아는 설명이면 기존 분류와 검색 정보를 재사용하고 관련 노트만 연결합니다. 새 설명이나 충돌이 있거나 판단이 애매하면 기존 NVIDIA 분석을 실행합니다. 같은 내용이라고 해서 원문이나 새 노트를 지우지는 않습니다. 각 자료의 출처를 따로 유지합니다.

모든 노트를 그래프로 만드는 것도 줄였습니다. 새로운 개념 관계, 평가에 영향을 줄 근거, 문항의 사고 구조가 있을 때 그래프를 만듭니다. 필요성이 분명히 낮으면 노트로만 저장합니다. 애매하면 그래프를 만듭니다. 그래프를 생략한 구간은 따로 기록하므로, 그래프에서 센 횟수를 전체 자료의 등장 횟수라고 부르지 않습니다.

## 교사 가설도 한 번 더 확인합니다

NVIDIA가 만든 가설을 Jev가 확인합니다. 다음 판단을 따로 보관합니다.

- 제공한 근거가 가설을 지지하는지, 반박하는지, 부족한지, 관계없는지
- 근거의 강도
- 어느 단원·문항 유형까지 적용할 수 있는지
- 추가 분석이 필요한지

관계없는 자료를 반례로 바꾸지 않습니다. 적용 범위가 애매하면 검토 대상으로 남깁니다. 이 판단을 하나의 ‘교사 정확도’ 숫자로 합치지 않았습니다. 기존 중요도 계산도 유지합니다.

## 느린 요청이 실패했을 때

**시간 제한은 늘리지 않았습니다.** 같은 큰 요청의 시간과 출력량을 늘려 세 번 보내던 동작을 없앴습니다.

이해 노트와 자료 그래프는 원문을 작은 구간으로 나누어 다시 처리합니다. 교사 가설은 근거 문장을 잘라버리는 대신, 완전한 근거 카드와 패턴의 선택 개수를 줄입니다. 축소는 최대 두 단계이며, 이미 끝낸 결과를 다시 만들지 않습니다. 다음 실행에서도 저장된 축소 기록을 따라갑니다.

문항 경계나 그림처럼 안전하게 자르기 어려운 작업은 실패를 감추지 않고 검토 대상으로 남깁니다. 검색 정보 생성만 실패하면 이미 만들어진 제목·주제를 임시 검색 정보로 저장하고 ‘추가 검토 필요’를 표시합니다. 이해 노트 본문은 보존합니다.

Jev가 연결되지 않거나 답이 불확실하면 기존 분석으로 넘어갑니다. 연결 실패를 ‘중요하지 않음’으로 처리하지 않습니다.

## 실제 작은 자료에서 확인한 결과

사용자가 올린 **「(3) 02. 기관계의 통합적 작용~.pdf」 6페이지의 저장된 노트**를 같은 상태에서 재처리했습니다. 비교 대상은 검색 정보 생성과 기존 노트 연결입니다. 문서 전체나 그래프 생성까지 비교한 결과는 아닙니다.

| 비교 | 기존 방식 | Jev가 먼저 판단한 방식 |
|---|---:|---:|
| 추가 NVIDIA 호출 | 2회 | 0회 |
| Jev 호출 | 0회 | 1회 |
| NVIDIA 응답 대기 합계 | 36.984초 | 0초 |
| Jev 응답 대기 합계 | 0초 | 0.297초 |
| 원문·노트 본문 보존 | 확인 | 확인 |

이 실험에서 Jev는 ‘같은 설명을 보강하므로 추가 추론은 필요하지 않다’고 판단했습니다. **그래프는 필요하다고 판단했습니다.** 그래서 이 결과를 ‘전체 분석이 0.3초에 끝났다’고 해석하면 안 됩니다. 처음 노트를 만드는 시간과 그래프를 만드는 시간도 위 표에 포함하지 않았습니다.

관련 없는 가설을 일부러 제시하는 실제 API 검사도 했습니다. Jev는 근거와 관계없다고 답했고, 적용 범위는 애매해 검토 대상으로 남겼습니다. 반박 근거로 처리하지 않았습니다. 최신 질문 문구에서도 API가 작동하는 것을 별도로 확인했습니다.

이 작은 비교에서는 양쪽 모두 시간 초과와 답변 길이 제한이 0회였습니다. **전체 PDF의 시간 초과가 줄었다고 입증한 것은 아닙니다.** 실제 교사 모델의 정확도 비교와 실제 청구 비용 측정도 아직 남아 있습니다. 원래 저장된 노트 역시 사람의 검토가 필요한 AI 해석입니다.

## 검증과 남은 범위

**전체 Python 검증 128개가 통과했습니다.** 새 검증 16개는 반복 설명, 새 설명, 충돌, 그래프 생략, 가설 지지, 관계없는 근거, Jev 실패를 확인합니다. 원문 위치 보존, 실패 후 재개, 낮은 신뢰도 처리, 질문·설정 변경, 노트 → 교사 모델 → 계획의 기존 흐름도 검사합니다. 웹 코드·지도·모션 검증과 설치된 패키지 호환성 검사도 통과했습니다. 이는 실제 교사 해석의 정확도 점수가 아닙니다.

이번에 실제로 연결한 부분은 **노트 분류 → 추가 추론 선별 → 자료 그래프 선별 → 교사 가설 검증**입니다. 교사 가설 생성 전 근거 선별, 교사 모델의 변경분만 갱신, 작은 학생 변화에 따른 계획 조정은 질문과 연결 지점을 준비했습니다. 자동으로 실행하는 기능은 다음 단계입니다.

자료 의미 이해, 그림 해석, 새 교사 가설 작성, 사람이 실행할 공부 행동 작성은 계속 LLM이 담당합니다. Jev에게 요약이나 교사 모델 전체 생성을 맡기지 않았습니다.
