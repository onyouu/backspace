# 자료·그림 이해 개선

## 구조

원본 → Native Text/PaddleOCR → 원문 검토 → 선택 페이지 시각 분석 → 개념·관계 추출 및 별도 검수 → 누적 자료 그래프.

텍스트 인식과 그림의 의미 해석을 분리한다. PDF는 전체 페이지와 가장 큰 이미지 영역 두 개를 함께 보낸다. PPTX는 이미지 영역 최대 세 개와 슬라이드 문맥을 사용한다. 화살표·분기·포함 관계를 실제 관찰과 조건부 해석으로 나누고, 불확실한 글자·기작은 별도 항목으로 남긴다. 원본 이미지와 인식 결과는 덮어쓰지 않는다.

## 사용

1. 선생님 자료 또는 시험범위에서 **원문 검토**를 연다.
2. 필요한 페이지를 선택한다. OCR 수정이 있으면 먼저 저장한다.
3. **이 페이지 그림 분석**을 누른다. 선택한 페이지만 NVIDIA를 호출한다.
4. 그림 이해의 관찰·연결 항목을 펼쳐 사용 이미지와 강조 영역을 확인한다. AI 해석은 검토가 필요한 결과다.
5. 모델 생성 또는 시험범위 분석을 실행하면 저장된 그림 문맥과 원본 이미지를 개념·관계 추출 및 별도 검수에 함께 사용한다. 페이지 전체를 자동으로 재분석하지 않는다.

현재 기본 시각 모델은 실제 한 페이지 호출을 완료한 `meta/muse-glimmer-30b`. `.env`의 `NVIDIA_VISION_MODEL`로 호환되는 이미지 입력 모델을 지정할 수 있다. API 키는 기존 `NVIDIA_API_KEY`를 사용하며 브라우저로 전달하지 않는다. 기존 텍스트 분석 모델은 그대로 유지한다. 이미지 호출은 SSE로 답변만 수집하고 종료 신호·완료 이유·JSON 스키마를 검사한다. 중단되거나 잘못된 응답은 성공 결과로 저장하지 않는다. Muse 이미지 호출은 `reasoning_effort=none`으로 긴 추론 출력을 생략한다.

```env
NVIDIA_VISION_MODEL=meta/muse-glimmer-30b
```

원문 검토의 실행 버튼은 NVIDIA API를 호출한다. 업로드·원문 검토를 여는 것만으로 호출하지 않는다. 해석 confidence는 모델 자기보고값이며 측정된 정확도나 Teacher Importance가 아니다.

## 보존 및 근거

- `normalized.json`: 기존 OCR 텍스트·좌표·최초 결과·수정 이력.
- `visual-p6.json` 등: 원본 SHA-256, 페이지/OCR 상태 해시, 사용 이미지 해시, 모델, 관찰·연결·불확실성, 분석 범위.
- `visual-<hash>.jpg`: 전송용 파생 이미지. 각 이미지 최대 170KB, 긴 변 최대 1800px. 원본은 그대로 보존한다.
- `visual_history/`: 새 시각 결과를 저장할 때 이전 기록 보존.
- 자료 그래프 assertion의 `visual_context_hash`: 해당 페이지 시각 보고서로 역추적. 이미지를 보았다고 개념 등장 빈도를 추가하지 않는다.

OCR 수정이나 원본 변경 시 이전 보고서를 그대로 재사용하지 않는다. 같은 페이지·같은 모델의 유효한 보고서는 재사용한다. 전송에 포함된 이미지 수와 전체 이미지 영역 수를 함께 기록한다.

## quote 오류

실제 자료의 `TCA\n\n회로`를 모델이 `TCA 회로`로 반환하면 이전의 연속 인용 검사에서 실패했다. 이제 글자·문장부호·순서를 그대로 유지하고 **공백만 다른 유일한 원문 구간**이 있을 때 정확한 원문으로 복원한다. 변경 전후를 추출 검토 기록에 남긴다. 여러 구간과 일치하거나 글자가 바뀐 경우에는 실패를 유지한다. 이 처리는 의미 관계의 타당성을 보장하지 않으므로 별도 검수를 유지한다.

## 참고한 공개 구현

- [RAG-Anything / ImageModalProcessor](https://github.com/HKUDS/RAG-Anything/blob/main/raganything/modalprocessors.py): 이미지와 인접 문맥을 함께 해석하는 구조. 프레임워크 전체를 도입하지 않고 현재 파이프라인에 적용했다.
- [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR): 기존 로컬 OCR과 복잡한 문서 인식 후보 조사. 이번 변경에서 기존 한국어 OCR 모델을 교체하지 않았다.
- [MinerU](https://github.com/opendatalab/MinerU): 페이지·블록·그림 위치를 보존하는 문서 파싱 참고. 설치하지 않았다.
- [Qwen3-VL](https://github.com/QwenLM/Qwen3-VL): 문서·공간 관계 이해의 추후 비교 후보. 현재 실행 모델로 도입하지 않았다.
- [NVIDIA Muse Glimmer API](https://docs.api.nvidia.com/nim/reference/meta-muse-glimmer-30b-infer): 이미지 입력 및 SSE 규약 참고.

## 현재 범위와 한계

그림 의미 분석은 선택 페이지 기능이다. 시험지의 페이지 해석은 검토용으로 제공하지만 문항별 reasoning 생성 전체를 자동으로 멀티모달로 전환하지 않았다. 기존 시험 문항의 OCR·시각 확인 절차는 유지한다. PPTX 전체 슬라이드 렌더링, 표·수식 전용 파서, 시각 해석의 사람 승인 워크플로는 후속 범위다.

자동 테스트는 구조·근거 보존·캐시·API 전송·실패 처리를 확인한다. 실제 전체 자료의 생물학적 분석 정확도나 Teacher Model 품질을 측정한 결과로 해석하면 안 된다. 원본 9개 PDF 전체를 다시 API에 보내거나 Teacher Model을 생성하지 않았다.

실제 한 페이지 호출 결과는 `output/visual_quality/live_result.json`, 요청 상태는 `output/visual_quality/usage_log.json`에서 확인한다. 시간 초과·형식 오류가 발생하면 원문 검토와 텍스트 분석 기능은 유지되며 시각 보고서는 새로 저장하지 않는다.

실제 PDF ‘(3) 02. 기관계의 통합적 작용~’ p6에서 전체 페이지·확대 이미지 2장을 사용해 관찰 4개와 연결 4개를 저장했다. 단백질→아미노산, 탄수화물→해당 과정, 피루브산→아세틸 CoA, 아세틸 CoA→TCA 회로의 방향을 확인했다. 성공 요청은 87.281초였다. 앞선 Kimi K2.5 접근 오류, Kimi K3 시간 초과, Muse JSON 형식 실패도 로그에 남아 있다. 전체 자료 성능이나 일관된 응답 속도를 검증한 결과는 아니다.

최종 검증: Python 전체 104개 테스트 및 `npm run check` 통과. 1440px·360px에서 그림 검토 UI를 확인하고 근거 이미지의 실제 로딩을 확인했다. 로컬 웹 작업으로 저장 결과를 재사용하여 신규 원격 요청 0회·`normalized.json` 불변을 확인했다 (`output/visual_quality/web_verification.json`). 실제 관계 4개를 원본과 대조했지만 페이지의 모든 분기·관계가 추출된 것은 아니며, 강조 좌표는 모델이 제시한 대략적 위치다.
